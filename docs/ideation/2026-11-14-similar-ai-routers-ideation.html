None of the 16 candidates survived. The routers in this class already ship rotation, stickiness, and failover. HoV Router already has those, and the proposals that would have made it "the best" on paper either undo a hold rule that exists because breaking it caused an outage, or restate a written measurement method as a missing feature. The bar was not lowered to fill a list.

Grounding Context

Codebase Context

HoV Router is a self-hosted load balancer for the operator's own provider accounts. It does not create quota. If every eligible account is unavailable, the request can still fail. Production is a Linux x86_64 binary behind a guard, SQLite only, deployed from origin/main. The README paste prompt is the setup path. macOS and native Windows installs are unverified. There is no npm package, container image, or binary for another platform.

Shipped account choice is session (the default), least-used, session-affinity, and session-drain-soonest with a strict variant. Drain-soonest does not rank by weekly reset alone. A fresh assignment sorts by fallback rung and tier, then weekly pace band, then earliest known future weekly reset as a tie-break inside one band. The worked example is the point of that order: an account at 66% with 66 hours left (hot) outranks one that resets sooner but only needs a slow burn. Codex owners stay until they are unavailable. Anthropic owners stay only while the prompt cache is certainly warm, meaning the previous turn was less than 5 minutes ago, and for at most 30 minutes. Sessions on a 1-hour cache TTL may still be warm after 5 minutes. The same paragraph says they move as before.

A child home is kept only by session-affinity and sticky session-drain-soonest. The default session strategy, least-used, and strict drain-soonest order every child turn again. That split is the written design. The dashboard offers Session and the two drain-soonest modes. It hides least-used and session-affinity. The comment calls both per-request spreading that can get accounts banned. The load-balancing doc calls session-affinity a spread of concurrent clients that still keeps cache locality inside each client. The comment is looser than the doc. The hide matches the documented spread.

A rate-limit hold's scope, duration, and evidence must name the same window. An upstream instruction may only shorten a hold. The usage cache is in-memory. After a restart, an unattributed reset takes a short backoff (30 seconds, doubling, capped at 5 minutes), not the far reset of a model window. That fix exists because honoring the wrong reset benched three healthy accounts 19 seconds after a deploy. Model-scoped windows stay out of account-wide utilization. Counting a Fable-only cap there removes every lane. Last-route protection was scoped and dropped: once wrong holds are capped at 5 minutes, a correct hold means the capacity is not there. Still open, and already written, not new: a pool-floor alarm, rendering bindingConstraint on the dashboard, and one eligibility predicate.

requests.timestamp is when the row was saved, not when the request started. Start is that timestamp minus response_time_ms. Of the switches that looked like remaps, 83% were two lanes interleaved in one session partition. Cache cost is judged by cache-write volume, not hit rate. Routing decisions are not logged at the default warn level, so the requests table is the measurement source, and the method for reading it is already written. A route alias is never priced. The Codex double-count was a second ingestion of the router's own proxied requests. The fix makes the scanner skip those rollouts. Pricing the alias would have hidden the duplicate. A window whose requests have aged out of retention is left unchanged, because a rebuild that cannot see every request it counted is unsafe.

A hosted tool dispatch cannot be released by retry or failover. That claim is about hosted dispatch, not about the first byte of an ordinary response. An authorized candidate is an account, a logical model, a physical model, and a rung. Mid-stream failover is already out.

The paste prompt tells the agent to verify a real request with the owner's help, and to report missing evidence as pending. That is the permitted owner-assisted path. It does not authorize a scripted call against an Anthropic account, and it does not refuse an unverified platform.

The class around it, from public project docs read as vendor claims, not as checked code. Account poolers (TeamClaude, maxpool, shunt, accountant, noria, codex-lb, codex-multi-auth) stretch one person's own subscriptions. Provider routers (CLIProxyAPI, OmniRoute, claude-code-router, 9router, opencodex) send traffic to many model vendors and sometimes bolt a pool on. Star counts sit on the any-model routers. That is one surveyor's inference, not a demand study. The upstream tombii README still describes a session strategy only. This fork has already left that description behind. Vendor READMEs are single-source.

What those docs treat as the difference between a usable router and a good one: classify the failure before retrying, cool an account down without sending probe traffic, pin a conversation to the account that holds the prompt cache, and check a budget before the request. This fork already pins, as an opt-in strategy with a 5-minute warm bound, and it already removed probes. No surveyed gateway documents cost-aware routing for a flat-rate subscription, which is the case that matters here. Reported postmortems judge a router by a failure the user sees rather than a green probe, by not failing over mid-stream, by an affinity clock that matches the real cache TTL, and by a cost figure that matches the bill. The 1-hour-versus-5-minute case is the one place this fork has written the opposite choice on purpose.

A Register article dated 20 February 2026, and maxpool's own README, are reported to say Anthropic banned third-party use of consumer OAuth tokens. Those pages were not re-fetched for this cut. A 12 November 2026 policy date came from a secondary site, not from Anthropic's policy page, and is not a basis. Becoming a resale proxy for other people's subscriptions is out. So is restoring PostgreSQL, npm publish, multi-arch or signed publishers, a container workflow, auto-refresh probes, a semantic cache of agent turns, mid-stream failover, pricing a route alias, gating on an inferred vendor field, lengthening a hold from an upstream header, writing a home before an accepted success, or ranking before the authorized set is compiled.

Topic Axes

  1. Account choice: which authorized account is tried, and on what evidence.
  2. Stickiness and failover: when a home stays, and what kind of failure is allowed to move it.
  3. The record: what a request row and a usage window are allowed to say.
  4. Client contract: what the client can rely on once a byte or a tool call has started.
  5. Who can run it: the setup promise, the verified platform, and whose accounts are in the pool.

Ranked Ideas

No idea survived. Sixteen candidates were cut, including three combinations. Each one either restated a decision the docs already made, cited a measurement method as if it were a missing routing rule, or would break a hold invariant those docs exist to protect.

The three items still open in the rate-limit note were not added back to fill the list. A pool-floor alarm, a dashboard render of bindingConstraint, and one eligibility predicate are already written there. The candidates that touched them asked for a different surface, or for a withhold the same note warns against.

What would change this cut is a measurement this page does not contain. The remap note already says how to read it from the requests table: start clock, true conversation parent, cache-write volume. A result that showed the default strategy's child reordering writing more cache than the 5-minute hold saves, or a confirmed failure class that leaves a warm home in place, would be new evidence. Neither was run here.

Rejection Summary

#IdeaReason rejected
C1 The default path keeps the child home The child-home lines say which strategies keep a home. They do not say the default must. The README sentence is failover under the operator's routing settings. The dashboard comment is loose, and the hide matches the documented spread of concurrent clients.
C2 Classify the failure before leaving model_capacity and credential_failure are declared and never assigned. A still-available owner is retained. A dead credential that drops the owner out of the available set already leaves as account_unavailable. The lines do not add a keep-the-home rule for a per-minute 429.
C3 The pin clock is the cache the client sent The warm bound is 5 minutes by decision. The load-balancing doc names 1-hour cache sessions and still moves them. Using the client's TTL as the pin would lengthen that hold. assignedAt is refreshed when the owner is retained.
C4 The candidate is the binding window, and the last proof survives a restart The restart bench was fixed by a short unattributed backoff. Persisting a proof that withholds is the failure that fix removed. The Fable split is a warning not to blend model windows into account exhaustion. One eligibility predicate is already an open item.
C5 Do not spend the only bay Withholding an account that could serve is the expensive error in the rate-limit note. Demoting the only remaining account for another lane is that withholding. Nothing cited shows the collision.
C6 A new session should not be pinned to the window that dies under it Inside a pace band, earliest future weekly reset is the shipped tie-break. The remap numbers measure the cost of moving a warm owner, which the warm hold already limits. They do not reverse the first pin.
C7 A pace-band move must beat the cache write, and a cold request should finish the window that dies tonight Ranking cold requests by soonest reset flips the worked example: a hot slow burn outranks a warm soon reset. A cache-write veto has no defined unit in the quotes, and the move is supposed to happen once the 5-minute cache is no longer certainly warm.
C8 The request row is the decision, on the start clock The remap note already says how to read the start clock, how to drop lane interleaving, and how to judge cache-write volume. It does not ask for new columns, or for a subscription headline that is not a dollar figure.
C9 An empty lane names the window, and a proved-soon reset can park the request The open item is a pool-floor log and a dashboard render of bindingConstraint, not window fields on a 503 or on /health. Parking until a reset does not create capacity. Last-route protection was dropped for that reason. The README says the request can still fail.
C10 A token event is inserted only under an identity the ledger already knows The alias tokens were a second ingestion. Pricing them would have hidden the duplicate. The fix skips proxied rollouts. An insert gate would also drop the separate unpriced-model case. An aged-out window is left unchanged on purpose.
C11 Fail closed on the tool contract before the first byte The irreversible claim is hosted dispatch, not the first response byte. The candidate shape has no tool-call field because authorization is account, model, and rung. No cited line shows an unrepresentable tool call leaving as prose. Mid-stream failover is already forbidden.
C12 The paste prompt is the license, and the binary emits it The paste prompt already says verify a real request with the owner's help. That is the permitted path, not a scripted probe. An unverified platform is not a refused one. Nothing cited makes the prompt a license, a binary output, or a field on the response.
C13 Codex session-id is not the per-conversation cache key The header shipped. The per-conversation key is the written choice, because one shared key thrashed a cache machine under Claude Code's fan-out. A session-scoped session-id over that key is the alternative the same note says not to adopt without new evidence.
X1 One leave rule Joins C2, C3, and the cache-write half of C7. None of those hold, and the combination would block failover of an unavailable owner.
X2 The window is the candidate Joins C4, C5, and the naming half of C9. Treating the binding window as the candidate is the blend the rate-limit note says removes every lane, plus a demotion that withholds a usable account.
X3 The row is the only record Joins C8 and C10. One is a measurement method that already exists. The other is an insert rule the alias note does not support.
